# Protein_ligand_Data_Analysis

General scripts for analysis of protein–ligand complexes generated by BoltzGen.

## Contents

| Script | Purpose |
| --- | --- |
| [`mutate_fasta.py`](mutate_fasta.py) | Generate combinatorial point-mutant FASTAs (alanine scans, saturation panels) from a multi-entry, multi-chain FASTA — ready to feed straight into BoltzGen / Boltz-2 as prediction jobs. |
| [`distribution_comparison.py`](distribution_comparison.py) | Compare two numeric distributions (e.g. `affinity_pred_value` with vs without MSA): histogram + KDE overlay, ECDF, Mann–Whitney U and Kolmogorov–Smirnov tests. |
| [`aa_frequency_comparison.py`](aa_frequency_comparison.py) | Compare per-position amino-acid frequencies between two sets of designed sequences (e.g. CDR-H3 design runs): grouped-bar overlays, a difference heatmap, and per-position Jensen–Shannon / total-variation / Spearman statistics. |
| [`affinity_screening/`](affinity_screening) | **Package.** Screening analysis of predicted binding scores against experimental Ka: correlations, strong-vs-poor ROC, cutoff trade-offs, five figures and a self-contained HTML report. Installable, with a CLI. |

## Requirements

- Python ≥ 3.8
- `pandas`, `numpy`, `scipy`, `matplotlib`
- `seaborn` and `scikit-learn` as well, for `affinity_screening`

```bash
pip install pandas numpy scipy matplotlib seaborn scikit-learn
```

## `mutate_fasta.py`

Takes a wild-type FASTA and a mutation specification, and writes every requested
combination of point mutations as a full-length FASTA entry.

### Input FASTA

One entry = **one prediction job**. Within an entry, chains are joined by `:`
(the BoltzGen / Boltz-2 multi-chain convention), and any number of chains is allowed:

```
>e2pico_scfv_m3rd
EVPLVESGGGLVKPGG...VTVSS:DILMTQTPSSMSVSLG...KLEVK
>some_other_construct
EVQLVESGGG...:DIQMTQSPSS...:GGGGSGGGGS
```

Every entry in the file is processed independently and yields its own output FASTA.
Entries may have different numbers of chains.

### Mutation specification

A dict of dicts — `{chain: {position: residues}}`:

```python
SPEC = {
    "VL": {                 # chain: name from CHAIN_NAMES, or 1-based chain index
        89: "A",            # alanine scan at this position
        90: "A",
        91: "A",
        96: "AGV",          # or a multi-residue panel: try A, G and V here
    },
    "VH": {
        100: ["D", "E"],    # lists work too
    },
}
```

- **chain** — a 1-based index into the `:`-split chains, or a label from
  `chain_names` (which is positional: `["VH", "VL"]` means chain 1 is VH, chain 2 is VL).
- **position** — a residue number (see *Numbering*).
- **residues** — a string or list of one-letter codes to substitute at that position.
  A single `"A"` is just the degenerate case, i.e. alanine scanning.

Combinations are taken across **all** chains in the spec jointly, and every
combination of allowed residues is enumerated at the chosen positions.

### Numbering

Positions index directly into the chain sequence — no prefix/suffix splitting needed.
By default numbering is 1-based over the chain. Use `numbering` to match an external
scheme per chain:

```python
numbering = {
    "VL": 24,                  # int  -> the chain's first residue is numbered 24
    "VH": [1, 2, 3, ...],      # list -> explicit numbering, must match chain length
}
```

Chains absent from `numbering` stay 1-based. An unknown position raises a
`ValueError` rather than silently mutating the wrong residue.

### Usage

Edit the block at the bottom of the script and run it:

```bash
python mutate_fasta.py
```

or import it:

```python
from mutate_fasta import generate_mutant_fastas

df = generate_mutant_fastas(
    "wt_scfvs.fasta",
    {"VL": {89: "A", 90: "A", 91: "A", 96: "A"}},
    out_dir="cdrl3_ala_muts",
    chain_names=["VH", "VL"],
    include_wt=True,
)
```

### Options

| Argument | Default | Meaning |
| --- | --- | --- |
| `chain_names` | `None` | Positional labels for the `:`-split chains; also usable as spec keys. |
| `numbering` | `None` | Per-chain residue numbering (int start or explicit list). |
| `min_mutations` | `1` | Lowest mutation order to emit. |
| `max_mutations` | `None` | Highest mutation order; `None` = all positions in the spec at once. |
| `skip_silent` | `True` | Drop picks where the substitution equals the wild-type residue. |
| `include_wt` | `False` | Prepend the unmutated parent as a `_WT` entry (useful as a prediction baseline). |
| `suffix` | `"_muts.fasta"` | Filename suffix for each job's output FASTA. |
| `manifest` | `"mutant_manifest.csv"` | Combined CSV of every mutant; `None` to skip. |

### Output

For each input entry, `<out_dir>/<job_id>_muts.fasta` with full-length sequences
(chains rejoined with `:`):

```
>e2pico_scfv_m3rd_V89A
EVPLVESGGG...VTVSS:DILMTQ...YYCAQYAQFPYTFGGGTKLEVK
>e2pico_scfv_m3rd_V89A_Q90A
...
```

Mutant names are `V89A_Q90A` style when a single chain is mutated, and
chain-qualified (`VH-C2A_VL-N101G`) when the combination spans chains.

Plus `<out_dir>/mutant_manifest.csv` and a returned `DataFrame` with columns:
`job`, `mutant_name`, `fasta_header`, `num_mutations`, `mutations`,
`sequence`, `fasta_path`.

### How many mutants?

For *n* spec positions each offering *r* substitutions, order *k* contributes
`C(n, k) · r^k` variants. A 4-position alanine scan over all orders gives
4 + 6 + 4 + 1 = **15** mutants; the same 4 positions with 3 candidate residues each
gives 12 + 54 + 108 + 81 = **255**. Bound this with `max_mutations` before pointing
a structure-prediction pipeline at the output.

### Notes

- Only the 20 standard amino acids are accepted; anything else raises `ValueError`.
- Duplicate sequences arising from different mutation paths are emitted once.
- Job IDs come from the first whitespace-delimited token of the FASTA header.

## `distribution_comparison.py`

Compares any two numeric distributions — typically the same scoring column from two
prediction runs (with vs without MSA, 1k vs 10k samples, mutant vs wild type).

### Inputs

Both the CLI and the helpers accept anything `load_values()` understands:

- a path to a `.csv` / `.tsv` / `.parquet` / `.xlsx` file, plus `--column`
- a `DataFrame` (with `column`; a frame with exactly one numeric column is auto-detected)
- a `Series`, list, or NumPy array

Non-finite values (`NaN`, `inf`) are dropped on load.

### Command line

```bash
python distribution_comparison.py \
    --a with_msa.csv --b without_msa.csv \
    --column affinity_pred_value \
    --label-a "With MSA" --label-b "Without MSA" \
    --plots kde ecdf hist \
    --save-dir figs --no-show \
    --stats-out figs/summary.json
```

| Option | Meaning |
| --- | --- |
| `--a`, `--b` | The two datasets. |
| `--column` | Column to compare in both; `--column-a` / `--column-b` override it per file. |
| `--sep` | Delimiter override for text tables. |
| `--label-a`, `--label-b` | Legend labels (also used to name saved PNGs). |
| `--xlabel`, `--title`, `--bins` | Figure cosmetics; `--xlabel` defaults to the column name. |
| `--plots` | Any of `kde` (density histogram + KDE), `ecdf`, `hist` (raw counts), or `none`. |
| `--no-tests` | Skip the statistical tests. |
| `--save-dir` | Write `<label_a>_vs_<label_b>_<kind>.png` here. |
| `--no-show` | Headless: switch to the Agg backend and don't open windows. |
| `--stats-out` | Write descriptive stats + test results as JSON. |

Output on stdout:

```
=== With MSA vs Without MSA ===
                With MSA: n=300    mean=   -1.2179 median=   -1.2383 std=    0.5098 range=[-2.7532, 0.3330]
             Without MSA: n=250    mean=   -0.7899 median=   -0.8027 std=    0.6988 range=[-3.5296, 0.6832]

Mann-Whitney U Test: U = 22716.0, p = 1.634e-15
Kolmogorov-Smirnov Test: D = 0.3093, p = 5.066e-12
Effect size: CLES = 0.303, Cliff's delta = -0.394
```

### As a library

```python
from distribution_comparison import (
    load_values, compare_distributions, ecdf_plot, distribution_similarity,
)

a = load_values(df_msa, "affinity_pred_value")
b = load_values(df_nomsa, "affinity_pred_value")

compare_distributions(a, b, label1="With MSA", label2="Without MSA",
                      xlabel="affinity_pred_value", bins=30)
ecdf_plot(a, b, label1="With MSA", label2="Without MSA")

stats = distribution_similarity(a, b, plot=False)   # tests only, no figure
```

`run_comparison(...)` is the one-call version the CLI uses — same keyword arguments
as the flags above, returning the summary dict.

### Interpreting the output

- **Mann–Whitney U** — is one distribution stochastically shifted relative to the
  other? Sensitive to a location shift, not to shape.
- **Kolmogorov–Smirnov** — largest gap between the two ECDFs; catches differences in
  spread or shape that a rank test can miss.
- **CLES / Cliff's delta** — effect size, reported because p-values shrink with sample
  size alone. CLES is the probability that a random draw from A exceeds one from B
  (0.5 = no difference); Cliff's delta rescales it to −1…+1.

### Notes

- Both plots use shared bin edges across the two datasets, so the histograms are
  directly comparable.
- KDE curves are skipped (with a printed note) for samples with fewer than two points
  or zero spread, since `gaussian_kde` cannot fit those.
- Statistical tests treat the two samples as independent; do not use them for paired
  per-complex comparisons.

## `aa_frequency_comparison.py`

Compares two sets of designed sequences position by position — e.g. CDR-H3 designs
where the whole loop was variable versus designs where part of it was held conserved.

### Preparing the sequences

`clean_and_trim()` pulls the sequence column, uppercases it, drops rows containing
anything outside the 20 standard amino acids, optionally splices in a fixed motif,
trims the flanks, and then **requires that everything left is the same length** —
frequency matrices are only comparable position-for-position:

| Option | Meaning |
| --- | --- |
| `--left-trim-a` / `--right-trim-a` | Residues to cut from each end of set A (`-b` for set B). |
| `--insert-a` + `--insert-at-a` | Splice a motif into every set-A sequence at a 0-based index, to re-align a set whose conserved stretch was absent during design. |
| `--query-a` / `--query-b` | pandas `query` filter applied first, e.g. `'affinity_pred_value < 0.1'`. |

The dropped-row counts and the observed length histogram are printed, so a ragged
input tells you what to trim instead of failing silently.

### Command line

```bash
python aa_frequency_comparison.py \
    --a all_designs_metrics_cdrh3_15top.csv \
    --b all_designs_metrics_cdrh3_conserved.csv \
    --column designed_sequence --left-trim-a 3 \
    --label-a "Full CDRH3 variable" --label-b "Conserved CDRH3" \
    --plots overlay heatmap js --top-n 20 --ncols 4 \
    --save-dir figs --no-show \
    --stats-out figs/position_stats.csv --save-freqs
```

`--plots` selects any of:

- `overlay` — grouped bars of the top *N* residues at every position (one panel per position)
- `heatmap` — `freq_B − freq_A` across all 20 residues × positions, diverging colour scale
- `js` — per-position Jensen–Shannon divergence profile with the mean marked
- `none` — statistics only

`--no-show` switches to the Agg backend for headless runs, `--save-dir` writes
`<label_a>_vs_<label_b>_<kind>.png`, `--stats-out` writes the per-position table, and
`--save-freqs` dumps both 20 × L frequency matrices as CSV.

### Statistics

`compare_position_distributions()` returns one row per position:

| Column | Meaning |
| --- | --- |
| `Top_<label>`, `top_*_freq` | Most frequent residue in each set and its frequency. |
| `Max_abs_diff`, `Mean_abs_diff` | Largest / mean per-residue frequency difference. |
| `Total_variation` | ½·Σ\|p−q\|, i.e. the fraction of probability mass that would have to move. |
| `JS_divergence` | Jensen–Shannon divergence in bits (0 = identical, 1 = disjoint). |
| `Spearman_rho`, `Spearman_p_value` | Rank agreement of the two 20-residue frequency vectors. |
| `Entropy_a_bits`, `Entropy_b_bits` | Shannon entropy per position (0 = fully conserved, log₂20 ≈ 4.32 = uniform). |

Followed by a printed summary (mean/max JS, mean total variation, mean/min rho).

### As a library

```python
from aa_frequency_comparison import (
    clean_and_trim, aa_frequency_matrix, compare_position_distributions,
    plot_all_position_overlays, plot_difference_heatmap, plot_js_per_position,
)

seqs_a = clean_and_trim(df_1, "designed_sequence", left_trim=3)
seqs_b = clean_and_trim(df_2, "designed_sequence")

freq_a = aa_frequency_matrix(seqs_a)      # 20 x L, columns 1..L
freq_b = aa_frequency_matrix(seqs_b)

stats = compare_position_distributions(freq_a, freq_b, "Variable", "Conserved")
plot_all_position_overlays(freq_a, freq_b, top_n=20,
                           label_1="Variable", label_2="Conserved")
```

`run_comparison(...)` does all of the above in one call (same keywords as the flags)
and returns `{"freq_a", "freq_b", "stats", "n_a", "n_b"}`.

### Notes

- Spearman rho over 20 frequencies is dominated by the many shared zeros at a
  well-behaved position; treat it as a coarse agreement check and read
  `JS_divergence` / `Total_variation` for the real signal.
- Every sequence is weighted equally — deduplicate or filter upstream (`--query-*`)
  if a run over-samples near-identical designs.
- Positions are 1-based **within the compared window**, after trimming, not in the
  parent chain.

## `affinity_screening/` (package)

Takes a table of predicted binding scores plus measured Ka values and answers the
question "where should we set the cutoff, and what does it cost us?" — correlations,
strong-versus-poor ROC, per-cutoff trade-offs, five figures and a single-file HTML
report.

### Install

```bash
pip install git+https://github.com/PrashanthJoseph/Protein_ligand_Data_Analysis.git
```

or, from a clone:

```bash
pip install -e .
```

Either gives you the `affinity-screening` command. Without installing, `python -m
affinity_screening ...` works from the repository root.

### Module map

| Module | Responsibility |
| --- | --- |
| `config.py` | `ScreeningConfig` — columns, class thresholds, cutoffs, score direction, output paths. Validates itself; loads from / saves to JSON. |
| `data.py` | Reading the table, checking required columns, coercing to numeric, dropping unusable rows, assigning experimental classes and screening decisions. |
| `metrics.py` | Correlations, strong-vs-poor ROC (with the Youden-optimal cutoff), per-cutoff performance and the full threshold sweep. No plotting, no printing, no files. |
| `plots.py` | The five figures, each writing one PNG and returning its path. |
| `report.py` | The self-contained HTML report, with figures embedded as base64. |
| `pipeline.py` | Orchestration (`run`) plus the console summary. |
| `cli.py` | `argparse` front end; `__main__.py` makes `python -m affinity_screening` work. |

### Command line

```bash
affinity-screening \
    --input gnina_best_pose_per_receptor_flex.csv \
    --tool-name GNINA_flex \
    --sequence-col receptor_id --affinity-col minimizedAffinity --ka-col "Ka (10^9)" \
    --score-direction lower_is_better \
    --proposed-cutoff -11.5 --rescue-cutoff -11 \
    --test-cutoffs -9 -10 -11 -11.5 -12 \
    --poor-ka 1 --strong-ka 7 \
    --output-dir score_cutoff_analysis_flex \
    --label-strip e2pico_scfv_ _M3rd \
    --save-config gnina_flex.json
```

`--save-config` writes the resolved settings as JSON, and a later run is then just:

```bash
affinity-screening --config gnina_flex.json
```

Any flag still overrides the file, so one config plus `--affinity-col CNNaffinity
--score-direction higher_is_better` re-runs the same analysis on a different score.
See [`examples/gnina_flex_config.json`](examples/gnina_flex_config.json).

Other flags: `--probability-col` (optional second output, analysed alongside the
score), `--show` (open windows instead of writing only), `--no-plots` / `--no-report`
/ `--no-export`, `--quiet`, `--sweep-points`, `--dpi`, `--sep`.

### As a library

```python
from affinity_screening import ScreeningConfig, run

config = ScreeningConfig(
    input_path="gnina_best_pose_per_receptor_flex.csv",
    tool_name="GNINA_flex",
    sequence_col="receptor_id",
    affinity_col="minimizedAffinity",
    ka_col="Ka (10^9)",
    proposed_cutoff=-11.5,
    rescue_cutoff=-11.0,
    test_cutoffs=[-9, -10, -11, -11.5, -12],
    output_dir="score_cutoff_analysis_flex",
)

outcome = run(config)                      # or run(config, source=my_dataframe)
outcome["results"]["cutoff_summary"]       # the comparison table
outcome["results"]["roc"]["affinity"]      # AUC, curve, Youden-optimal cutoff
outcome["report"]                          # path to the HTML report
```

The layers are usable on their own — `prepare()` for a cleaned, classified frame,
`cutoff_metrics()` / `threshold_sweep()` for numbers with no side effects,
`plots.make_all()` for figures, `write_report()` for the HTML.

### Score direction

`score_direction` decides both the screening rule and how the ROC score is oriented:

| Setting | Retain when | Example |
| --- | --- | --- |
| `lower_is_better` (default) | `score < cutoff` | GNINA `minimizedAffinity`, docking energies |
| `higher_is_better` | `score > cutoff` | probabilities, `CNNaffinity`, pKd |

`probability_direction` does the same for the optional probability column
(default `higher_is_better`).

### Experimental classes

Ka is split into poor (`Ka < poor_ka_threshold`), intermediate (inclusive of both
bounds) and strong (`Ka > strong_ka_threshold`). The class labels in the legends and
tables are generated from those numbers, so changing a threshold relabels everything
consistently. ROC drops the intermediate class and asks only how well the score ranks
strong above poor.

### Outputs

Written to `output_dir`:

```
01_<tool>_score_vs_Ka.png              05_<tool>_cutoff_comparison.png
02_<tool>_cutoff_tradeoff.png          <tool>_screening_classified_data.csv
03_<tool>_class_distributions.png      <tool>_cutoff_metrics.csv
04_<tool>_ROC_strong_vs_poor.png       <tool>_threshold_sweep.csv
                                       <tool>_affinity_screening_report.html
```

Per-cutoff metrics include how much of the pool is eliminated, what fraction of poor
binders that removes, how many strong binders survive, the purity of the rejected
pool, and the fraction of the retained pool that is strong.

### Notes

- The `rescue_cutoff` must sit on the looser side of `proposed_cutoff` for the given
  score direction; a rescue band that would be empty is rejected by `validate()`.
- The Youden-optimal cutoff is fitted on the same data it is evaluated on, so it is
  optimistic — treat it as an upper bound, not a prospective threshold.
- Figures are written with the Agg backend unless `show=True`, so the CLI runs fine
  over SSH.
